# OrangeCTL — план разработки

## Как пользоваться планом

- `[x]` — задача выполнена и подтверждена текущим кодом.
- `[ ]` — задача ещё не выполнена.
- `[?]` — реализация есть, но она неполная или её нужно проверить.

Задачу можно отмечать выполненной только после реализации её критериев готовности и прохождения соответствующих тестов.

## Текущее состояние

- Готов базовый Go-проект с десятью конфигурационными слотами.
- Работают команды `init`, `help`, `list`, `validate` и `version`.
- Реализованы строгая загрузка JSON и правила валидации для конфигурационных слотов.
- Управление процессами, просмотр логов, интерактивное меню и релизная упаковка ещё не реализованы.
- Go установлен и доступен в PATH.
- Автоматические тесты пакетов `internal/config` и `internal/paths` проходят.
- Запуск тестов пакета `internal/cli` блокируется Windows Application Control при попыттии запуска собранного тестового `.exe`.

## 3. Валидация конфигурации

- [x] Не требовать команды и рабочую папку у выключенного слота.
- [x] Для включённого слота требовать непустой `working_directory`.

- [x] Для включённого слота требовать непустой `start_command`.

- [x] Проверять `env_file`.
  - Отклонять отсутствующий путь, директорию, симлинк и небезопасные Unix-права доступа.

- [x] Проверять синтаксис ключей в `environment`.
- [x] Проверять, что конфигурация не раскрывает содержимое `env_file` или значения окружения в ошибках.
- [x] Возвращать структурированные ошибки валидации, пригодные для программной обработки.

## 5. Менеджер процессов

- [x] Создать пакет `internal/process` и интерфейсы для тестирования системных операций.
- [x] Реализовать `orangectl start <slot>`.
  - Проверить имя, загрузить и полностью провалидировать конфиг.
  - Не запускать выключенный или уже работающий слот.
  - Выполнить пользовательскую команду через `/bin/sh -c` без добавления CLI-аргументов в строку команды.
  - Установить рабочую директорию через `exec.Cmd.Dir`.
  - Передать окружение через `exec.Cmd.Env`.
  - Запустить процесс в отдельной группе процессов.
  - Направить stdout и stderr в настроенный лог.
  - Обнаружить немедленное аварийное завершение.
- [x] Реализовать объединение окружения в порядке `os.Environ()` → `env_file` → `environment`.
- [ ] Реализовать `use_sudo` только для команды конкретного слота.
  - Критерий: сам `orangectl` не требует постоянного запуска от root.
- [x] Реализовать атомарный PID-файл состояния.
  - Сохранить slot, PID, время запуска процесса, рабочую директорию и идентификатор `/proc`.
  - Не использовать один PID как достаточное доказательство принадлежности процесса.
- [x] Реализовать проверку личности процесса перед `status`, `stop` и `restart`.
  - Проверить существование `/proc/<pid>` и время запуска процесса.
  - Проверить ожидаемую рабочую директорию и команду.
  - Проверить владельца и отсутствие симлинка у PID-файла.
- [ ] Обрабатывать устаревший PID-файл, не затрагивая чужой процесс.
- [ ] Реализовать `orangectl status [slot]`.
  - Без аргумента показать краткий статус всех слотов.
  - С аргументом показать подробный статус одного слота.
- [ ] Реализовать `orangectl stop <slot>`.
  - Если настроен `stop_command`, выполнить его и проверить завершение процесса.
  - Иначе отправить `SIGTERM` группе процессов и ждать до тайм-аута.
  - После подтверждённой остановки удалить PID-файл.
- [ ] Добавить настраиваемый тайм-аут остановки с дефолтом 10 секунд.
- [ ] Добавить флаг `--force` для отправки `SIGKILL` после неуспешного `SIGTERM`.
- [ ] Реализовать `orangectl restart <slot>`.
  - Использовать `restart_command`, если он задан.
  - Иначе выполнить последовательность `stop → подтверждение → start`.
- [ ] Определить и реализовать поведение `auto_restart`.

## Постоянные ограничения

- [ ] Не добавлять в репозиторий реальные пользовательские проекты, токены, API-ключи, `.env`, домашние пути и заранее заполненные команды.
- [ ] Поставлять все слоты выключенными и пустыми.
- [ ] Не собирать shell-команды из непроверенных CLI-аргументов.
- [ ] Не запускать весь CLI от root без необходимости.
- [ ] Не добавлять внешнюю библиотеку, если задача надёжно решается стандартной библиотекой Go.

> OrangeCTL не знает о конкретных программах пользователя. Он безопасно управляет десятью универсальными слотами, описанными конфигурационными файлами.
