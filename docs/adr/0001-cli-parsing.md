# ADR 0001: CLI parsing approach

- Status: Accepted
- Date: 2026-08-08
- Deciders: project maintainer

## Context

orangCLIPLAN.md (этап 4) требует решить, переводить ли разбор команд
и флагов на [Cobra](https://github.com/spf13/cobra) или остаться на
стандартной библиотеке Go (`flag`, ручной диспетчер).

Текущая реализация `internal/cli/cli.go` — это 124 строки:

- диспетчер верхнего уровня — `switch args[0]`;
- глобальные флаги добавляются через `flag.NewFlagSet` (этап 4 ещё не
  реализован);
- команды `init`, `list`, `validate`, `help`, `-h`, `--help`
  реализованы без внешних зависимостей;
- тесты (`internal/cli/cli_test.go`) подменяют `stdout`/`stderr` и
  аргументы — без внешней mock-инфраструктуры.

## Decision

Остаёмся на стандартной библиотеке Go. Cobra не подключаем.

## Rationale

1. **Размер кодовой базы.** У проекта одна команда верхнего уровня и
   десять слотов. Cobra даёт вложенные команды (`orangectl config edit`,
   `orangectl logs follow`), автогенерацию help, shell completion,
   man-pages — это инфраструктура для проектов уровня `kubectl` или
   `docker`. Здесь она не используется ни одной фичей.

2. **Зависимости.** Cobra тянет `pflag`, `cobra`, `errors` и
   транзитивно `stretchr/testify` при использовании в тестах. Каждая
   новая зависимость — это поверхность атаки, supply-chain риск
   (Этап 11, постоянные ограничения orangCLIPLAN.md: «Не добавлять
   внешнюю библиотеку, если задача надёжно решается стандартной
   библиотекой Go»).

3. **Тестируемость.** Текущая функция `Run(args, stdout, stderr) int`
   принимает всё нужное для тестов как параметры — никакого
   `os.Exit`, глобального состояния, init-блоков. Cobra делает то же
   самое через `cmd.Execute()` + `SetOut/SetErr`, но добавляет лишний
   слой абстракции и требует `cmd.SetArgs(...)` в каждом тесте.

4. **Помощь и ошибки.** Cobra умеет генерировать длинный help по
   описаниям команд. У нас сейчас `const usage = "..."` в `cli.go` —
   этот же текст тривиально расширяется по мере добавления команд.

5. **Стоимость миграции.** Переход на Cobra — это переписывание
   `cli.go` (~120 строк) и `cli_test.go` (~300 строк), плюс
   гарантия, что семантика ошибок и кодов возврата сохранится.
   Выгода — автогенерация help и вложенные подкоманды, которые пока
   не нужны.

## Consequences

Положительные:

- ноль зависимостей в `go.mod`;
- код `internal/cli/cli.go` читается сверху вниз: одна `Run`, одна
  константа `usage`, набор функций по командам;
- тесты выполняются без mock-инфраструктуры.

Отрицательные (явные):

- help-текст нужно поддерживать вручную;
- вложенные команды (`orangectl config edit`) придётся реализовать
  через `switch args[0]; switch args[1]`, без синтаксического сахара
  Cobra;
- автодополнение для shell придётся писать отдельно, если потребуется.

## Когда пересмотреть

ADR пересматривается, **любое** из условий:

- в плане появляется ≥3 уровней вложенных команд
  (`orangectl <group> <command> [subcommand]`);
- ≥2 команды требуют одинаковых глобальных флагов с нетривиальной
  логикой (repeated flags, env-binding, completion);
- проект публикуется как библиотека для сторонних CLI;
- появляются требования к shell-completion в README.

До тех пор это решение не пересматривается.
